Fourth run [44076363721](https://github.com/Duckhanh149/DayMind-Smart/actions/runs/44076363721), source3bec4d0: shared259 tests/build pass. Manual signature verification passed but the Simulator refused launch (NSPOSIX162; actual crash report SIGKILL / Taskgated Invalid Signature). The manual signing approach was wrong: iOS Simulator entitlements belong in Mach-O __TEXT,__entitlements / __ents_der; putting restricted iOS entitlements into the macOS code signature causes launch rejection. Removed the manual signer entirely; no runtime Keychain fallback or weakened assertions.

Corrected native leg lets Xcode manage Simulator signing (CODE_SIGNING_ALLOWED=YES, CODE_SIGN_IDENTITY=-, no development team), and lets Flutter's device-targeted test use its standard signing path. Final normal Simulator build keeps Xcode signing enabled. The initial no-codesign compilation check remains separate. A read-only helper verifies Simulator metadata/embedded sections; it does not sign binaries. Three boundary checks reject device/macOS/malformed bundles. No Apple account, certificate or provisioning secret; real iPhone signing is still phase7. Failure extraction now includes native test-result JSON and disposable Simulator security logs.
